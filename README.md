# 管住手了吗（Panji）

> 一个把「交割单 → 你自己的纪律规则 → 逐日自查」跑通的开源复盘工具。
> 判定 100% 由你勾选的规则决定，程序不产出任何买卖结论。

![license](https://img.shields.io/badge/license-AGPL--3.0--or--later-blue)

## 它解决什么问题

多数人复盘失败不是因为不想复，是因为「记不下来」和「记了不算」。

1. 券商 App 能导出交割单，但没人愿意手工录进 Excel。
2. 事后看 K 线，总觉得「我当时是想好的」——因为没有一条事先写下的规则可以对照。
3. 有规则也没用，因为没人逐条检查你今天违反了哪几条。

这个工具把这三件事串起来：**传交割单 → 写你自己的规则 → 系统逐日告诉你哪几条没守住。**

## 它明确不做什么

这一节比上一节重要。

- 不接实时行情，不预测价格，不推荐标的，不评估选股，不生成任何收益预期。
- 不提供「AI 帮你选股」「智能诊股」「买卖点提示」这类功能，也不打算提供。
- 不做策略回测，不接交易接口，不下单。
- 判定结果只回答一个问题：**「你自己写的这条规则，那天守住了吗？」** 它不评价你的规则好不好。

## 能跑什么

- **交割单解析**：5 种版式——`card`（东海 App 成交卡片）、`horizontal`（通用横排）、`vertical`（通用竖排）、`guangda`（光大对账单「一笔两行」）、`ths_pc`（同花顺 PC「历史成交」横表，无方向列与数量列，靠发生金额对账、成交金额÷均价反算）
- **规则引擎**：十余条可勾选规则模板（开盘冷静期、收盘前禁买、不追当日最高、不越跌越补、单笔占比上限、单日买入笔数上限、反复买卖……）+ 自定义规则，模板见 `server/rules.js` 的 `TEMPLATES`
- **确定性判定**：同一份交割单 + 同一组规则 = 同一份结果，可复现。AI 只参与措辞润色，不参与判定
- **纪律随身卡**：四组自填容器，开盘前 / 盘中 / 收盘后自查
- **回看**：单日 K 线与分时、到期日自查
- **票档案与批注**：按标的聚合你自己的成交，写你自己的批注
- **本机备份**：导出 / 导入 JSON，不依赖账号

## 5 分钟本地跑起来

需要 Node.js 18+，无运行时依赖（不用 `npm install` 装任何包）。

```bash
git clone <你的仓库地址>
cd guanzhushou
cp server/.env.example server/.env
npm start                      # 默认 http://localhost:3000
```

`server/.env` 里至少要选一个 OCR 来源：

| `OCR_PROVIDER` | 说明 |
|---|---|
| `mock` | 不连任何服务，返回内置合成文本，适合先看界面 |
| `textin` | 需 `TEXTIN_APP_ID` / `TEXTIN_SECRET_CODE` |
| `tencent` | 需 `TENCENT_SECRET_ID` / `TENCENT_SECRET_KEY` |
| `baidu` | 需 `BAIDU_OCR_API_KEY` / `BAIDU_OCR_SECRET_KEY` |
| `local` | 指向自建 OCR 服务，需 `LOCAL_OCR_URL`（可选 `LOCAL_OCR_TOKEN`） |

不想把交割单发给云服务？本仓带 `local_ocr/`，可以在内网起一个 OCR 容器：

```bash
docker build -t panji-ocr local_ocr/
docker run -p 8080:8080 panji-ocr
# server/.env 里设 OCR_PROVIDER=local、LOCAL_OCR_URL=http://127.0.0.1:8080
```

## 架构

```
浏览器（原生 JS，无框架）
  ├─ 上传页：可选遮挡涂抹 → 图片上传
  ├─ 记录页 / 档案页 / 纪律卡：数据存 localStorage，不上传
  └─ 回看页：读本机或本地 data 目录的 K 线

服务端（Node，单进程，无数据库，无第三方依赖）
  ├─ /api/ocr     → server/ocr.js：供应商适配（textin / tencent / baidu / local / mock）
  ├─ /api/rules   → server/rules.js：规则模板与参数
  ├─ /api/judge   → server/judge.js：确定性检测 + 报告组装
  └─ /api/kline   → 本地行情目录（自备数据才可用）
```

三句话：

1. **前端零上传**：复盘档案默认只存在浏览器 localStorage。
2. **服务端无状态**：不存你的成交，不存你的账号，没有登录。
3. **判定确定性**：`server/rules.js` 是纯函数式检测器，无随机、无模型调用。

## 交割单解析支持哪些版式

| 版式 | 特征 | 状态 |
|---|---|---|
| `card` | 东海证券 App 成交列表，锚点行形如 `买 20261019 10:14:50` | 支持 |
| `horizontal` | 通用横排，一行一笔 | 支持 |
| `vertical` | 通用竖排 | 支持 |
| `guangda` | 光大对账单，一笔两行、上下错位字段 | 支持 |
| `ths_pc` | 同花顺 PC「历史成交」横表，无方向列、无数量列 | 支持 |

**不支持什么**（明确写出来比藏着好）：

- 一笔被拆成两行、且没有锚点可依的折行记录
- 截图不含日期列且不含时间列的流水
- 期货、期权、融资融券的完整保证金流水（只支持担保品买卖的方向词识别）
- 非 A 股市场

识别不确定时，字段置空并标低置信，交给你在复核页补录——**不猜。**

## 数据与隐私

这个工具处理的是最敏感的一类个人数据（真实成交记录），所以隐私设计写在代码里，不是写在政策里：

- **上传前遮挡**：`public/features/mask.js`，选图后先在本地涂抹遮挡块，合成新图再上传；遮挡坐标只记在本机。
- **主动丢弃字段**：`server/parser.js` 的 `SCRUB_RE`，逐行丢弃含「股东姓名 / 股东账号 / 资金账号 / 身份证 / 客户号 / 手机号」的行，只计数不留内容。
- **本机存储**：复盘档案存 localStorage，本机备份导出为 JSON。
- **无账号即可用**：自托管版不需要注册、不需要登录。

## 已知限制

- 档案页的「解锁」按钮属于托管版能力：本仓不含授权模块，点击会提示需要在线授权，不影响其余功能。
- `public/data/`、`public/builtin/` 是行情数据目录，本仓不含数据文件，回看页只能读你自己放入的本地数据；`replay_readonly.html` 在无内置数据时显示空态。
- 图鉴页（`collection.html`）与科普页（`learn.html`）只说明内容库边界，不含动画与图鉴资源。
