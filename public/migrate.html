    3 · 二维码迁移（v1 不做）

    两条路径都评估过，在「纯前端、档案数据不经服务器中转」的红线内都不成立：

    • ✗ 一次性短码：短码必须由服务器签发并在另一台设备校验，没有服务器这条就跑不起来。
    • ✗ 分片二维码（共 N 张 / 第 i 张）：仓库内没有二维码依赖，也不允许 CDN。编码器可以自研，但接收端还需要摄像头实时解码器，仓库同样没有，且无相机环境无法验证正确性；真实档案通常 20KB 以上，会拆成十几张密排二维码，扫描与失败重试体验不可接受。

    v1 的现实替代：导出 .json 文件 → 用微信 / 隔空投送 / 数据线传到新设备 → 在新设备打开本页导入。

    迁移范围与边界

    • 会迁移：账本、纪律档案、规则、复发索引、豁免 / 理由 / 止损标记、持仓与资金、月度复盘、图鉴与引导状态等档案记录。
    • 不会迁移：设备级功能开关（换机后重新选择）、支付身份标识、未完成支付快照、本机开闸记录。
    • 本机存储上限按 3.5MB 设闸：超过时导出 / 导入都会明确拒绝并告诉你实际大小，不会静默失败。
